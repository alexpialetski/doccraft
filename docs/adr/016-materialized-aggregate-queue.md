# ADR 016: Materialised cross-package aggregate queue; epic lane; status vocab

**Status:** Accepted

## Context

[ADR 014 §5](014-monorepo-package-docs.md) decided the root `queue.md`
lists **only root-scoped** stories — "not an aggregate of every package" —
and that a cross-package "what can I work on anywhere" view is an
*on-demand, not committed* artifact.

The only consumer (audio-stage) does the opposite. Its root `queue.md` is
a **hand-maintained cross-package aggregate** ordered by milestone → epic,
listing stories from all four declared packages plus root. This is the
direct source of the staleness the user reports: when any package's story
closes, three files must change (the story, the package queue, and the
hand-built root aggregate), and nothing owns that third edit.

Worse, the `planning-hierarchy` extension's `queue-artifact-types`
fragment instructs "group work by active milestone first, then by epic
dependency" — which is injected into the *same* `doccraft-queue-audit`
body that (per ADR 014 §5) says "root = root-scoped only". The baked skill
contains two mutually unsatisfiable instructions. The deterministic
reconcile also orders by `queueAudit.laneFrom: ["area","slice"]` — `epic`
is not a lane — so the mechanical pass cannot reproduce the milestone/epic
structure the user maintains by hand, guaranteeing drift.

Finally, audio-stage declares a richer terminal vocabulary
(`done-no-promote`, `abandoned`, `absorbed`) but core queue-audit treats
only `done` as satisfying a prerequisite, so those stories silently fail
to unblock dependents.

The user is the only consumer; a breaking change to the queue layout is
acceptable.

## Decision

Three coupled changes to `doccraft-queue-audit`, refining ADR 014 §5
(which stays in force for everything except the aggregate clause).

### 1. The cross-package aggregate becomes a generated artifact

The milestone/epic cross-package roadmap is **generated by
`doccraft-queue-audit`, not hand-edited**. It is regenerated on demand
(and as the reconcile step of `doccraft-close`, ADR 015). The root
`queue.md` is no longer hand-maintained as an aggregate; the generated
view is the single place cross-package ordering lives, so no human or
agent mirrors package changes up by hand.

This resolves the contradiction: the core skill no longer claims "root =
root-scoped only" *and* "order root by milestone/epic". Instead, root and
per-package queues stay scope-local, and the aggregate is an explicit
generated surface that composes them.

### 2. `epic` is a sanctioned `laneFrom` dimension

`queueAudit.laneFrom` accepts `epic` alongside `area`/`slice`. When set,
the deterministic reconcile groups by epic (and, with the
`planning-hierarchy` extension, orders epics by milestone then epic
`depends_on`). The structure the user keeps by hand becomes the structure
the algorithm produces — they can no longer diverge.

### 3. Reconcile honours the full terminal vocabulary

A story `status` is "satisfied / closed" if it is any terminal value in
the project's configured `story.status` set (e.g. `done`,
`done-no-promote`, `absorbed`), not the literal `done` alone. The audit
reads the vocabulary from `doccraft.json` rather than hardcoding `done`.

## Consequences

- **+** Root queue stops rotting: nobody hand-maintains a cross-package
  aggregate, so the close-time staleness disappears.
- **+** The self-contradiction baked into `doccraft-queue-audit` is gone —
  one ordering story instead of two.
- **+** The milestone/epic view the user wants is preserved, just
  generated instead of curated; reconciles with ADR 014 §5 by making the
  aggregate explicit rather than forbidden-but-built-anyway.
- **+** `epic`-as-lane and full-vocab terminals are config-driven; no new
  bespoke machinery.
- **−** Refines ADR 014 §5 — the "aggregate is never committed" clause is
  replaced by "aggregate is generated." ADR 014 otherwise stands.
- **−** `doccraft-queue-audit` grows a generation mode on top of its
  reconcile mode; a meaningful skill edit. The generated surface MUST be
  clearly marked as generated so no one hand-edits it.
- **−** Per-package queues plus a generated aggregate is more files than
  one hand-curated list — but they no longer fall out of sync.

## Alternatives considered

- **Keep the hand-maintained aggregate, teach close + audit to update it**
  — rejected by the user. More LLM steps per transition and the aggregate
  can still be left stale on any missed step.
- **Strict ADR 014 §5 (root = root-scoped, roadmap in a separate index)**
  — viable, but the user wants the milestone/epic view to *be* the working
  queue, not a side index. Generation gives that without hand-maintenance.
- **Resolve the contradiction by deleting the extension's ordering
  fragment** — rejected; the milestone/epic ordering is genuinely wanted.
  The fix is to make it producible by the algorithm, not to drop it.
- **`epic` ordering as injected prose only** — rejected; prose cannot
  override the deterministic `laneFrom` pass, which is what caused the
  drift in the first place.
